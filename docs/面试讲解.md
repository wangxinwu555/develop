# 面试讲解与设计取舍

## 60 秒项目介绍

我实现了一个基于 Python 和 LangGraph 的售后工单 Agent。用户提出换货需求后，
系统可以补全订单信息、调用订单接口、检索政策、校验条件，并在用户确认后创建模拟工单。
模型负责理解和选择工具，后端负责权限、条件和写入。项目还实现了状态持久化、
审批恢复、工单幂等以及固定案例评测，重点解决工具执行和业务状态的一致性问题。

默认规则模式用来复现流程；真实模型模式通过支持 Function Calling 的 API 接入。
是否接过真实模型、取得什么评测结果，应按自己的实际运行情况补充。

## 高频追问

### 为什么用 LangGraph？

任务包含工具循环、暂停审批、服务重启后的恢复，需要明确状态和流程分支。
LangGraph 的节点、状态与 checkpoint 适合展示这些能力。仅做一次问答时没有必要使用复杂图。

### 这算 Agent 还是固定工作流？

真实模型模式中，模型根据需求与工具结果选择是否追问、调用什么工具、何时完成。
写入和审批由确定性程序控制。规则模式是测试替身，路径预设，不能把它当 LLM 自主决策。

### 为什么没有一开始做多 Agent？

当前工具和业务范围小，单 Agent 足够。多 Agent 会增加延迟、上下文传递和故障定位复杂度。
只有出现确实需要隔离的职责、上下文或独立评测任务时，再拆分。

### RAG 的数据流程是什么？

使用 PyPDFLoader 读取 PDF，RecursiveCharacterTextSplitter 切分并保留来源页码，
Embedding 编码后写入持久化 Chroma。提问时只编码问题，检索相似块，把原文作为工具结果
提供给聊天模型。默认哈希向量是无密钥测试替身，真实语义模型需要单独接入并评测。
业务数据在 SQLite，知识向量在 Chroma；两者职责不同。

### 为什么向量模型变化需要重新建库？

不同模型的向量空间可能不同，即使维度一致，也不能混用。索引指纹记录模型、
服务地址、切分参数和 PDF 内容，变化时要求重建；新快照成功后再启用，避免失败破坏旧索引。

### 如何避免越权？

工具 schema 不接受 user_id；后端从会话身份注入。订单 SQL 同时过滤 user_id。
会话读取和审批也检查所有权。公开 Demo Token 只是测试身份，尚未实现生产认证。

### 人工确认怎么做？

准备申请时 interrupt，并给前端返回申请内容与审批编号。审批接口校验会话与编号，
通过 Command 恢复图。聊天文本不能绕过后端审批接口直接创建工单。

### 恢复为什么不会重复写入？

恢复可能从节点开头重跑，所以 interrupt 前不产生业务写入。写入使用审批编号作为幂等键，
数据库同时约束申请编号和订单编号。checkpoint 本身不等于 exactly-once。

### 工具失败或模型失败怎么办？

工具失败结构化返回模型，模型可以解释或有限重试。模型调用设置超时和有限 SDK 重试，
Agent 还有最大步数。失败后已有 checkpoint 保留，重试接口从待执行节点继续。
日志不输出底层异常文本，避免将请求头或密钥回传给用户。

### 怎样评价效果？

固定案例评测状态、工具、来源、工单数量、未确认写入、耗时和 Token usage。
自动断言只覆盖部分行为，模型回答还要人工审阅，不能把小样本通过率称为全面准确率。
目前的测试集是演示回归集，未做独立的真实用户保留集实验。

### 还有哪些不足？

无真实商家与生产用户；认证为演示值；只支持单进程；没有流式输出；上下文未压缩；
政策语料小；扫描 PDF 未支持 OCR；真实模型的幻觉与工具选择需要实际评测。向量 API 已做离线适配测试，
真实 embedding provider 未配置时不能宣称已完成真实接口验收。

## 简历写法

先用这些不依赖虚构指标的描述，并删去你没有实际理解或运行的部分：

- 使用 Python、FastAPI、LangChain 组件和 LangGraph 实现模拟售后工单 Agent，
  支持订单查询、政策检索、多轮信息补全和人工确认后的工单创建。
- 实现 PDF 加载、文本切分和 Chroma 持久化向量检索，保留来源页码；
  默认用哈希向量验证流程，接入真实 Embedding 后再补实际效果。
- 通过会话身份注入和数据库过滤实现演示用户隔离；使用 checkpoint、
  审批编号和数据库唯一约束处理暂停恢复及重复写入。
- 建立覆盖正常与异常场景的测试和行为评测，记录工具路径、任务状态、耗时与 Token usage。

接真实模型后再补“接入了什么模型、案例规模、具体失败、实际改进结果”。
不写“企业级生产落地”“准确率99%”“服务数万用户”等未经证实的内容。
