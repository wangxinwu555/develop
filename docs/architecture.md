# 架构设计

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `api.py` | HTTP 路由、输入校验与沙箱身份解析 |
| `service.py` | 会话所有权、会话锁、状态响应与失败恢复 |
| `graph.py` | 模型调用、工具循环、人工确认和 checkpoint |
| `tools.py` | 工具 schema、参数校验和服务端用户身份注入 |
| `business.py` | 订单读取、资格校验、审批记录和工单幂等写入 |
| `ingest.py` | PDF 加载、清理、分块与索引快照管理 |
| `embeddings.py` | 嵌入服务适配和离线哈希编码器 |
| `retrieval.py` | 索引校验、向量检索、阈值过滤与来源组装 |

## 知识库生命周期

建库流程由 `scripts.ingest` 独立执行：

```text
PDF → 页面 Document → 文本清理 → 分块 → Embedding → Chroma
```

每个文本块保留文件名、页码、政策编号和唯一 ID。索引指纹包括源文件内容、切分配置、
编码器身份和索引版本。有效索引可复用；重建写入独立快照目录，核对记录数量后更新 manifest。
正式 manifest 通过临时文件替换，指向可用于查询的新快照。

在线检索加载 manifest 指定的快照，不重新解析 PDF。检索词通过同一编码器转成向量，
Chroma 返回相近的文本块，服务按阈值过滤并附带来源。向量相似度不等于证据充分性。
结构化业务规则保存在 `data/policies.json` 中，检索原文不覆盖后端资格校验。

## Agent 执行

```text
START → agent → tools → agent → … → END
```

模型收到系统规则、会话消息和工具 schema，返回普通回复或工具调用。
后端执行工具，将结果编码为 `ToolMessage` 追加到会话，再调用模型。
模型调用有超时和有限重试；Agent 步数达到上限后停止执行。

工具包括订单查询 `get_order`、政策检索 `search_policy`、资格校验 `check_exchange`
和申请准备 `request_exchange`。用户身份来自服务端上下文，不作为模型可填写参数。

## 审批与幂等

`request_exchange` 必须单独调用。工具完成只读校验后，图通过 `interrupt()` 暂停并返回待确认信息。
用户确认恢复执行时，后端重新检查资格并创建工单；取消时不创建工单。

审批决定持久化。相同决定支持重放，不同决定与过期审批被拒绝。
工单申请编号和订单编号有唯一约束，防止重复确认或恢复造成重复写入。
当前业务规则每个订单最多创建一个工单，尚未包含关闭后重新申请的生命周期。

## 状态与存储

- SQLite 业务库：订单、工单和审批决定。
- SQLite checkpoint：消息、工具执行状态及待恢复任务。
- Chroma：政策原文、向量、元数据和文本块 ID。
- manifest：索引指纹、编码器身份、文件清单及当前快照。

同一进程内，会话锁将单个会话的操作串行化。多个服务进程需要分布式锁和适配的存储方案。

## 故障处理与可观测性

工具错误以结构化结果返回给模型；底层异常不将请求头、密钥或数据库路径返回给用户。
服务层保留失败任务状态，恢复接口从 checkpoint 继续执行。
业务写入成功但模型总结失败时，恢复不应重复提交审批或创建工单。

执行事件记录节点、工具、耗时、结果和服务商返回的 token 用量。
模型输出与检索资料在客户端通过文本节点渲染，避免被作为 HTML 执行。
